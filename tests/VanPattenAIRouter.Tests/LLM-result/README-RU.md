## LLM тестовые программы

**Русский** | [English](README.md)

В этом каталоге находятся Python-скрипты для комплексного тестирования функциональности VanPatten AI Router во всех трёх режимах виртуальных провайдеров и граничных случаях.

## Тестовые скрипты

| Скрипт                            | Описание                                                                            |
|-----------------------------------|-------------------------------------------------------------------------------------|
| `test_auto_free_mode.py`          | Тестирует режим `vanpatten/auto-free` — маршрутизация только к бесплатным моделям   |
| `test_auto_mode.py`               | Тестирует режим `vanpatten/auto` — маршрутизация ко всем моделям (бесплатные + платные) |
| `test_specific_model_mode.py`     | Тестирует режим `vanpatten/{model-name}` — конкретная модель с failover             |
| `test_rate_limit_and_failover.py` | Комплексные тесты ограничения частоты запросов и failover                           |
| `test_stream_stability.py`        | Стресс-тест стабильности потока                                                                                    |

## Запуск тестов

### Предварительные требования
```bash
pip install aiohttp
```

### Переменные окружения
```bash
export VANPATTEN_API_URL="http://localhost:10080"
export VANPATTEN_API_KEY=""  # Опционально, для аутентифицированных эндпоинтов
```

### Запуск отдельных тестов
```bash
python test_auto_free_mode.py
python test_auto_mode.py
python test_specific_model_mode.py
python test_rate_limit_and_failover.py
```

### Запуск всех тестов
```bash
for test in test_*.py; do
    echo "Running $test..."
    python "$test"
    echo "---"
done
```

## Охват тестами

Каждый тестовый скрипт покрывает:

### `test_auto_free_mode.py`
- ✅ Получение списка доступных бесплатных моделей
- ✅ Непотоковое завершение с auto-free
- ✅ Потоковое завершение с auto-free
- ✅ Множественные запросы для проверки failover
- ✅ Граничные случаи (минимальные запросы)

### `test_auto_mode.py`
- ✅ Получение списка всех моделей (бесплатные + платные)
- ✅ Непотоковое завершение с auto
- ✅ Потоковое завершение с auto
- ✅ Сравнение с режимом auto-free

### `test_specific_model_mode.py`
- ✅ Проверка доступности модели через админ-провайдер
- ✅ Непотоковый запрос к конкретной модели
- ✅ Потоковый запрос к конкретной модели
- ✅ Множественные запросы для верификации стабильного failover
- ✅ Тестирование нескольких моделей (gemini, llama, mistral)

### `test_rate_limit_and_failover.py`
- ✅ Проверка статистики rate limit
- ✅ Тестирование пакетных запросов (burst)
- ✅ Верификация поведения failover
- ✅ Failover в потоковом режиме
- ✅ Точность оценки токенов
- ✅ Обработка одновременных запросов (непрерывность обновления модели)

### `test_stream_stability.py`
- ✅ Длительное стриминг-тестирование (5+ минут на сценарий, 15+ минут всего)
- ✅ Сложные аналитические промты, требующие обширной генерации
- ✅ Три последовательных сценария: `vanpatten/auto`, `vanpatten/auto-free`, `vanpatten/auto`
- ✅ Прогревающий запрос перед основным стресс-тестом
- ✅ Прогресс-отчёт каждые 50 чанков
- ✅ Обнаружение разрывов соединения (досрочное закрытие)
- ✅ Обнаружение пустых потоков (нет полученного контента)
- ✅ Обнаружение медленных чанков (паузы > 5 секунд)
- ✅ Измерение времени до первого чанка (TTFC)
- ✅ Измерение пропускной способности (символов/секунда)
- ✅ Логика повторных попыток с экспоненциальной задержкой (2 retry)
- ✅ Сохранение результатов в JSON с меткой времени
- ✅ Сравнительная сводка по всем сценариям
- ✅ Отслеживание провайдера/модели из метаданных ответа
- ✅ Мониторинг производительности и памяти

## Ожидаемые результаты

Все тесты должны пройти успешно при выполнении условий:
1. VanPatten AI Router запущен на `http://localhost:10080`
2. Настроен и активен хотя бы один провайдер KiloCode
3. Лимиты частоты запросов не превышены во время выполнения тестов

## Примечания

- Тесты по умолчанию используют `vanpatten/auto-free` как самый безопасный режим
- Тесты конкретных моделей требуют, чтобы модель существовала на хотя бы одном активном провайдере
- Тесты rate limit могут упасть, если лимиты провайдера превышены во время тестирования
- Потоковые тесты проверяют корректную обработку SSE-чанков
